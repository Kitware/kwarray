# kwarray Quality Improvement Plan

This directory contains an ordered set of planning documents produced by a full
repo audit (2026-07-09, branch `dev/0.7.2`, version 0.7.2 unreleased). Every
bug listed as "confirmed" was empirically reproduced against this checkout
with numpy 2.4.4 on Python 3.12. An executor agent should be able to work
through these documents in order without re-running the audit.

## Repo conventions the executor must know

- **Test command**: `python3 -m pytest tests/ --xdoctest kwarray/ -q`.
  The `pytest.ini` addopts already configure `-p no:doctest --xdoctest
  --xdoctest-style=google`. Baseline at audit time: **125 passed, 61
  skipped, 0 failed** (skips are optional-dep gates; torch/scipy/pulp/kwimage
  were not installed in the audit env, but scipy was available to the
  distributions auditor — install what you can before verifying).
- **Doctests are the primary test vehicle.** Most functions are verified via
  xdoctest blocks in docstrings, gated with
  `# xdoctest: +REQUIRES(module:<name>)` for optional deps. When you fix a
  bug whose doctest encodes the buggy output, you MUST update the doctest in
  the same commit.
- **`kwarray/__init__.py` is generated by mkinit.** Do not hand-edit the
  autogen block; regenerate with `mkinit kwarray --relative --nomods -w`
  (mkinit is pip-installable). After regenerating, confirm the explicit
  `__all__` and lazy sections still match.
- **`setup.py`, CI configs, and much scaffolding are generated by xcookie**
  (`pyproject.toml [tool.xcookie]`). Hand edits are acceptable but note them;
  ideally change the xcookie config so a future regen doesn't revert them.
- **`.pyi` stubs exist for most modules.** If you change a signature, update
  the matching stub. Stubs currently import from `nptyping` (being removed in
  phase 07).
- **CHANGELOG.md** has an `Unreleased 0.7.2` section — add entries for every
  user-visible fix. Behavior changes (not just crash fixes) should be called
  out explicitly.
- **CI source of truth is `.gitlab-ci.yml`** (GitHub Actions may mirror it).
  `appveyor.yml` is stale (phase 01/07 handles it).
- **Optional deps**: torch, scipy, pandas, pulp, numba are all optional.
  `import kwarray` must never require them. Several confirmed bugs are
  "requires optional dep unnecessarily" — preserve the lazy-import style
  (`sys.modules.get('torch')` etc.) in all fixes.

## Decision points requiring maintainer judgment

Most fixes are unambiguous (crashes, formula errors). These change public
behavior and are flagged inside the docs with **[DECISION]** markers:

1. `equal_with_nan` returns inverted results — the fix changes output for all
   existing callers (02, item 1). The current behavior is indefensible, but
   flag loudly in CHANGELOG.
2. `normalize(mode='sigmoid')` default `beta` is the span, not the center
   (02, item 13) — fixing changes numeric output of existing pipelines.
3. `ifloor`/`iceil` return int32 while `iround` returns int64 (05, item 8).
4. `Uniform.__params__` is declared `(high, low)` so positional
   `Uniform(0, 10)` sets `high=0, low=10` (03, item 12) — fixing is breaking
   for positional callers.
5. `sparse_assignment(maximize=True)` semantics differ between the sparse
   path and the dense fallback (04, item 4).
6. Python 3.8 support: keep or drop (07, item 1).
7. The misspelled `'propogate'` nan-policy string appears in public APIs in
   two modules — fix requires a deprecation alias (02 item 4, 04 item 15).

## Verification protocol (applies to every phase)

1. Before starting a phase, run the full suite to confirm a green baseline.
2. Each fix should come with a test (doctest or `tests/` file) that fails
   before the fix and passes after. Phase 06 consolidates, but do not defer
   the regression test for a bug you just fixed.
3. After each phase: `python3 -m pytest tests/ --xdoctest kwarray/ -q` must
   be green, and `python3 -c "import kwarray"` must work in an environment
   WITHOUT torch/scipy installed (torch-optionality is a hard requirement).
4. Run `python3 -m flake8 kwarray/ --select=E9,F` (syntax/undefined-name
   class errors only) as a cheap sanity gate if flake8 is available.
